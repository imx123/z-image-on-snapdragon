# Snapdragon 8 Elite bring-up

## Milestone 0: reference capture

Run the official Z-Image-Turbo Python pipeline at 512x512, batch one, and save a fixed seed, prompt, generated image, and intermediate tensors. The Android runtime should be compared against this reference.

Download the checkpoint with tools/download_model.py. It requires the ModelScope Python SDK and writes only under models/.

## Milestone 1: graph export

Use tools/export_manifest.py to record the intended graph boundaries and fixed shapes. Export each graph from the official Python implementation in a separate environment; do not silently substitute a different text encoder or VAE.

Expected graph boundaries:

text_encoder: prompt tokens -> conditioning embeddings
transformer: latent + conditioning + timestep -> predicted latent/noise
vae_decoder: latent -> RGB image

The downloaded Turbo snapshot contains approximately 6.15B float32 Transformer parameters, 4.0B bfloat16 Qwen3 text-encoder parameters, and an 84M bfloat16 VAE. The text encoder must therefore be treated as an independently quantized, cacheable component rather than assumed to fit in the NPU alongside the Transformer.

## Milestone 2: Android CPU reference

Implement and validate the scheduler and JNI lifecycle before enabling hardware backends. The runtime must support cancellation, errors, and explicit model paths.

## Milestone 3: Qualcomm backends

Compile the text encoder for QNN HTP first. Keep a CPU fallback for unsupported operators. Bring up the Transformer on Adreno GPU in FP16 before attempting weight-only INT4. VAE stays FP16 GPU until numerical parity is established.

The first concrete export target is `vae_decoder.onnx`, generated by `tools/export_vae_onnx.py` from the local ModelScope snapshot. QNN SDK binaries are optional and must be supplied separately; no Qualcomm SDK is downloaded by this repository.


## Acceptance criteria

- Fixed 512x512, batch-one input
- Eight diffusion steps for Turbo
- Peak memory is measured, not inferred
- Output is visually comparable to the Python reference
- Unsupported QNN operators fail with a clear fallback message
After export, run `tools/verify_onnx.py build/vae_decoder.onnx`. The first target is a fixed-shape graph: `[1,16,64,64] -> [1,3,512,512]`.

For the text encoder, run `tools/prepare_text_inputs.py` first. Do not export a full dynamic Qwen3 graph until the QNN SDK and operator partitioning strategy are available.

The fixed-shape text encoder export uses the system Python 3.14 environment for Transformers model loading, then QAIRT's isolated Python 3.12 runtime for QNN conversion. Both stages are offline against the local ModelScope snapshot.

QAIRT 2.49 dry-run requires ONNX opset 17 for the exported Qwen3 mask graph; opset 18 reports `LessOrEqual: unsupported version`.

Before formal QNN conversion, consolidate the exported tensor files with `tools/consolidate_onnx_external_data.py`; QAIRT's MatMul optimization is unreliable with hundreds of per-tensor external files.

## Transformer ONNX export notes (2026-08-15)

- Export script: `tools/export_transformer_onnx.py` (fixed shapes: latent `[1,16,64,64]`, timestep `[1]`, cap_feats `[512,2560]`; output `[1,16,64,64]`).
- The Z-Image transformer uses **complex64 RoPE** (`torch.polar` + `view_as_complex`), which the TorchScript ONNX exporter rejects with `ScalarType ComplexFloat is an unexpected tensor scalar type`. The local diffusers copy at `python312/Lib/site-packages/diffusers/models/transformers/transformer_z_image.py` was patched (backup: `transformer_z_image.py.bak_complex`) to use a mathematically identical real-valued rotation: `precompute_freqs_cis` now emits interleaved `[cos, sin]` float32 pairs (same layout as complex64 storage) and `apply_rotary_emb` applies `(a*cos-b*sin, a*sin+b*cos)`. Verified bit-close to the complex version (max abs diff ~5e-7).
- `torch.nn.utils.rnn.pad_sequence` is not ONNX-traceable; `export_transformer_onnx.py` monkey-patches the module-level binding inside the transformer with a static cat/stack equivalent.
- RoPE applies per-axis (`axes_dims=[32,48,48]`, `axes_lens=[1536,512,512]`); the flat `freqs_cis` passed to attention is `[batch, seq, dim/2]` interleaved.
